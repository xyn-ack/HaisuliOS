In a microkernel design, process management and POSIX-style system calls (fork, exit, getpid) are split between the kernel and a user-space server. The kernel provides the raw low-level mechanisms, while a user-space Process Manager server handles the high-level operating system policy.

What stays in the Microkernel (Mechanism)

A true microkernel (such as L4, seL4, or QNX) strictly minimizes kernel code to IPC, basic scheduling, and low-level memory primitives. It knows nothing about POSIX concepts like fork(), getpid(), or process hierarchies. Instead, it handles:
• Threads and Execution Contexts: Creating, destroying, and context-switching raw CPU execution threads.
• Address Spaces: Allocating and mapping raw page tables or capability spaces (C-spaces) to isolate memory.
• Inter-Process Communication (IPC): Passing messages and transferring capabilities between threads and servers.
• Low-Level Scheduling: Deciding which thread runs next on the CPU based on priority.

What lives in the User-Space Server (Policy)

To provide a standard POSIX or Unix-like environment, a dedicated user-space server (often called the Process Manager or PM, as seen in MINIX 3 or QNX's procnto) implements the actual process abstraction:
• Process Identity (getpid, getppid): The server assigns and tracks numeric Process IDs (PIDs), parent-child trees, and process groups.
• Process Creation (fork, exec): When a program calls fork(), it sends an IPC message to the Process Manager. The server then asks the kernel to allocate a new address space and thread, copies or sets up Copy-on-Write memory mappings, and registers the new PID.
• Termination and Signals (exit, wait, kill): The Process Manager handles zombie states, cleans up file descriptors (often by messaging the File System server), notifies parent processes, and delivers POSIX signals.

Summary of the Split


Feature	Microkernel (Mechanism)	Process Server (Policy)
Core Abstraction	Threads and address spaces	Processes, PIDs, and process trees
getpid()	Unaware of PIDs	Looks up and returns the caller's PID
fork()	Creates empty address space/thread	Duplicates memory state and assigns PID
exit()	Destroys thread/address space on request	Handles exit status, zombies, and signals
